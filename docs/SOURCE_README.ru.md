# Исследовательская база выборов в Госдуму — снимок на 30.09.2026

Полная предоставленная база с добавленными адресами, населёнными пунктами и координатами ранее сопоставленных УИК.
Название/год выборов сохранены из исходных материалов; архив не удостоверяет окончательные официальные итоги.
Включены **все партии, все кандидаты, оба типа бюллетеней, ДЭГ и все строки протоколов**. Карта uiks.top использует только ЕР по партийным спискам обычных УИК, не смешивая их с ДЭГ.

## Распаковка

Это ZIP с усиленным сжатием **LZMA**: оно позволяет разместить полную базу с SQLite без сокращения таблиц. Используйте актуальный **7-Zip** или Python 3 (модуль zipfile). Некоторые встроенные распаковщики ZIP не поддерживают этот метод. Для Python:

```bash
python -m zipfile -e duma-2026-research-2026-09-30.zip ./data
```

После распаковки структура и форматы CSV/SQLite обычные; специального программного обеспечения для работы с данными не требуется.

## Полнота и расчёты

Полный реестр: 177 931 протокол обычных УИК, 194 ДЭГ, 3 661 494 строки протоколов. Отсутствуют 4 831 протокол УИК, считая оба вида бюллетеня; перечень — missing_protocols.csv.
По партийным спискам сохранены 89 132 протокола обычных УИК: 88 799 в 85 регионах, 333 вне обычного регионального слоя. Партийные протоколы отсутствуют для Луганской Народной Республики, Донецкой Народной Республики, Запорожской и Херсонской областей (2 249 известных УИК). Отсутствие координат не означает отсутствие протокола.
ДЭГ хранится отдельно через dataset=deg; не присоединяйте такие протоколы к физическим УИК и не суммируйте их с обычными автоматически.

Формула карты: **голоса ЕР / (действительные + недействительные бюллетени) × 100%**. Нулевой знаменатель даёт NULL. Региональные суммы включают УИК без координат. Архив оставляет исследователю выбор знаменателя и методики; percent_source не заменяет самостоятельный расчёт.

```sql
SELECT p.region_name, SUM(r.votes) AS er_votes,
       SUM(p.valid_ballots + p.invalid_ballots) AS ballots,
       100.0 * SUM(r.votes) / NULLIF(SUM(p.valid_ballots + p.invalid_ballots), 0) AS er_percent
FROM protocols p JOIN party_results r USING(protocol_key)
WHERE p.dataset='uik' AND p.ballot_type='party_list'
  AND r.party_id LIKE '%edinaya-rossiya%'
GROUP BY p.region_name;
```

Источники унаследованной карты: RED https://doi.org/10.1038/s41597-026-07590-9 и Harvard Dataverse https://doi.org/10.7910/DVN/DFGNTP (CC BY 4.0). Сохраняйте происхождение данных при повторном использовании.
Контрольные суммы обновлены для всех файлов; sqlite_integrity, внешние ключи, численность исходных таблиц и совпадение географических значений CSV/SQLite проверены повторно.

## Быстрый старт

Основной формат — **реляционные CSV в UTF-8**, одна строка на сущность или строку протокола. Дополнительно `elections.sqlite`: те же данные с числовыми типами, ключами, индексами и SQL-представлениями. JSON используется только для описания состава, схемы и проверок. Сырых JSON-ответов, HTML, кэшей, токенов и журналов запросов в архиве нет.

Это **снимок собранных материалов**, не заверение окончательных итогов и не гарантия полноты официального сайта. Название «2026» унаследовано от прежнего сбора; при этой упаковке карточка выборов повторно не запрашивалась. В протоколах сохранены исходные идентификаторы выборов и даты, чтобы это можно было проверить независимо.

Состав: 91,381 УИК; 177,931 протоколов УИК; 194 протоколов ДЭГ; 3,661,494 строк протоколов. Недоступных в сохранённых материалах протоколов УИК: 4,831. Это реестр обнаруженных УИК, а не заново подтверждённая общероссийская полнота.

## Файлы и связи

- `precincts.csv` — полный справочник УИК: регион, ТИК, номер УИК, округ, адрес, координаты и происхождение/качество обогащения. Ключ `uik_id`; **номер УИК сам по себе не уникален**. `tik_code` — код из прежнего обхода иерархии, не гарантированно официальный номер ТИК.
- `protocols.csv` — одна строка на полученный протокол. Обычные УИК (`dataset=uik`) и ДЭГ (`dataset=deg`) явно разделены. Содержит все 12 стандартных числовых показателей, статус, флаги подписания, исходные UUID, время публикации и URL.
- `protocol_lines.csv` — **все строки всех сохранённых протоколов**, включая показатели, партии и кандидатов. Названия вынесены в `line_labels.csv`; соединение по `label_id` возвращает точный `infoText`, включая исходные переносы строк. `record_ordinal` — порядок в ответе, `line_number` — исходный `infoPrintNum`, `info_num` — исходный `infoNum`. Поля `category`, `description_category`, `group_name`, `is_elected` также сохранены.
- `party_results.csv`, `candidate_results.csv` — удобные длинные таблицы голосов. Связь с протоколом по `protocol_key`, с географией — по `uik_id`. Для ДЭГ `uik_id` пустой: регионально-окружной протокол нельзя привязать к отдельному физическому УИК. ДЭГ нельзя смешивать с обычными УИК без явного решения о методике суммирования.
- `address_enrichment.csv` — все 5,427 попыток обогащения, включая неудачные и неоднозначные. Привязаны строго по коду региона и номеру УИК; каждое совпадение единственно. Здесь сохранены и строки адресов со статусом `invalid_address`: они **не считаются пригодным адресом**.
- `parties.csv`, `districts.csv` — прежние справочники. Их пустые поля не заполнялись догадками. Полные наименования в результатах сохранены; `party_id`/`candidate_id` — технические ID, не официальные реестровые номера. Для ДЭГ при отсутствии старого ID используется хеш имени; сопоставлять с обычными УИК следует по точному имени, а не автоматически по ID.
- `missing_protocols.csv` — актуальные пропуски снимка: для каждого УИК проверено наличие обоих типов бюллетеня. `not_in_collected_snapshot` не утверждает, что протокол никогда не публиковался.
- `validation_issues.csv` — обнаруженные при новой упаковке расхождения суммы голосов и действительных бюллетеней (0). Значения не исправлялись и не отбрасывались.
- `collection_issues.csv` — исторические предупреждения сборщика; часть может относиться к прежним проходам. Для текущего покрытия использовать `missing_protocols.csv`, не число этих предупреждений.
- `source_ledger.csv` — прежний журнал источников ЦИК; ссылки остаются ссылками на источник, исходных файлов здесь нет. Источник адресов указан построчно, координат — в `geocoding_source`. Ссылки на raw/ в старых заметках журнала описывают исходную коллекцию, а не содержимое этого архива.
- `manifest.json` — реальные количества, покрытие, происхождение входных материалов и их SHA-256.
- `schema.json` — список колонок и типы; `validation_summary.json` — выполненные проверки; `SHA256SUMS` — контрольные суммы всех файлов кроме самого списка.

## Строки протокола и исправление прежней сводки

В этой поставке сводные показатели заново прочитаны из сохранённых протоколов, а голоса сверены с прежней объединённой выгрузкой. В прежней таблице поля переносных и стационарных ящиков были переставлены. Здесь корректно: **строка 7 — переносные**, **строка 8 — стационарные**. Добавлены отсутствовавшие в сводке строки 4, 5 и 12. Исходные голосовые данные не менялись.

Соответствие стандартных строк:
1 `registered_voters` — избиратели в списке;
2 `ballots_received` — полученные бюллетени;
3 `early_votes` — выданные досрочно;
4 `ballots_issued_stationary` — выданные в помещении;
5 `ballots_issued_outside` — выданные вне помещения;
6 `cancelled_ballots` — погашенные;
7 `portable_box_ballots` — в переносных ящиках;
8 `stationary_box_ballots` — в стационарных ящиках;
9 `invalid_ballots` — недействительные;
10 `valid_ballots` — действительные;
11 `lost_ballots` — утраченные;
12 `unaccounted_ballots` — не учтённые при получении.

`ballot_position` в таблицах результатов — исходный номер **строки протокола**, а не обязательно порядковый номер партии/кандидата в бюллетене. `percent_source` — процент как опубликован источником, сохранён текстом; нельзя считать, что его знаменатель — число действительных бюллетеней. Для собственной аналитики вычисляйте знаменатель явно. Неизвестный показатель — NULL, **не ноль**.

Статус `recounted` выставлен по флагу `repeated`; `final` — только когда оба флага подписания истинны; иначе `preliminary`. Это консервативная маркировка по доступным полям, не юридическая экспертиза утверждения итогов. `source_created_at`/`protocol_updated_at` — время источника, не время скачивания. Время создания архива находится отдельно в manifest; время скачивания адреса — в `address_retrieved_at_utc`.

## Адреса и координаты

Проверка адресов проводилась только для 5,427 УИК из отдельной входной таблицы. Пригодный официальный адрес (`address_status=ok`) есть у 2,629; координаты — у 2,627. В этой версии архив дополнительно обогащён географией старой карты; правила и итоговый охват описаны в начале README.

`address_status`: `not_requested` — не входил в этот этап; `ok` — пригодный адрес из сервиса комиссий ЦИК; `not_found` — отсутствует совпадение; `ambiguous` — неоднозначность; `invalid_address` — строка адреса непригодна. Сервис возвращает адрес комиссии: отдельно подтвердить, что это фактическое помещение голосования, по этим материалам нельзя.

Координаты получены **Яндекс Геокодером**, а не ЦИК. Система WGS84 / EPSG:4326, `latitude` — широта, `longitude` — долгота, десятичные градусы; в GIS порядок точки обычно `(longitude, latitude)`.

Уверенность: **high — 692**, **medium — 1,695**, **low — 240**. `high` — строгая проверка адресного совпадения прежним геокодером; `medium` — первый ответ, дом с `exact`/`number`, без полной собственной сверки; `low` — приблизительный дом, улица, населённый пункт или другой объект. **Ни одна из этих меток не является натурной проверкой здания УИК.** Для точечных карт зданий исключайте low; для строгого анализа используйте high. Сохранены точность (`geocoding_precision`), тип объекта (`geocoding_kind`), метод и распознанный адрес. Две ошибки геокодирования также сохранены.

## Примеры SQL

```sql
-- Голоса партий по регионам: только обычные УИК
SELECT p.region_name, r.party_name, SUM(r.votes) AS votes
FROM party_results r JOIN protocols p USING(protocol_key)
WHERE p.dataset = 'uik'
GROUP BY p.region_name, r.party_name;

-- Строго сопоставленные точки для карты
SELECT uik_id, region_name, address, latitude, longitude
FROM precincts WHERE geocoding_confidence = 'high';

-- Восстановить читаемые строки одного протокола
SELECT l.line_number, d.label, l.value, l.percent_source
FROM protocol_lines l JOIN line_labels d USING(label_id)
WHERE l.protocol_key = (SELECT protocol_key FROM protocols LIMIT 1)
ORDER BY l.record_ordinal;

-- Проверить пропуски по регионам и бюллетеням
SELECT region_code, ballot_type, COUNT(*) FROM missing_protocols
GROUP BY region_code, ballot_type;
```

SQLite-представления: `precinct_totals` (только УИК), `deg_protocols` (только ДЭГ), `mappable_party_results` (голоса с координатами; уверенность нужно фильтровать самостоятельно).

## Проверки и ограничения

Проверены уникальность ключей, сохранение всех строк полученных протоколов, неотрицательные целые значения, точная сверка прежних голосов с протоколами, единственность адресного соединения, диапазоны координат, совпадение чисел строк CSV и SQLite, `PRAGMA integrity_check` и внешние ключи. Итоги — в `validation_summary.json`. Для каждого УИК отсутствующие протоколы не подставляются нулями. Полнота публичного дерева заново не проверялась. Границ участков/округов, новых адресов, нового геокодирования и расчётной явки в этом архиве нет.

Собрано офлайн из неизменённых локальных материалов многопроходного сбора и обогащения. Исходная коллекция остаётся отдельно; её raw-файлы не входят в поставку. Контрольные суммы: `sha256sum -c SHA256SUMS` после распаковки.
